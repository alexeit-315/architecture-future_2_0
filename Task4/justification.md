# Обоснование конфигурации инфраструктуры для Yandex.Cloud

## Архитектурные решения

### Сетевая архитектура
- **VPC с разделением на публичные/приватные подсети**: Изоляция компонентов для безопасности
- **NAT только для web-сервера**: Ограничение прямого доступа к внутренним сервисам

### Выбор ресурсов ВМ
- **Web Server (2 CPU, 4GB RAM)**: Оптимально для обработки HTTP-трафика
- **App Server (4 CPU, 8GB RAM)**: Увеличенные ресурсы для бизнес-логики
- **DB Server (4 CPU, 16GB RAM)**: Память оптимизирована для работы СУБД

### Дисковая подсистема
- **network-ssd для активных данных**: Высокая производительность 
- **network-hdd для бэкапов**: Экономичное хранение резервных копий
- **Раздельные диски**: Изоляция ОС и данных приложений

## Преимущества подхода Infrastructure as Code

### Воспроизводимость
- Идентичное развертывание в разных окружениях
- Версионность изменений через Git
- Автоматизация процесса развертывания

### Масштабируемость
- Легкое изменение параметров ВМ и дисков
- Модульная архитектура для повторного использования
- Поддержка (в будущем) multi-cloud стратегии

### Безопасность
- Контроль изменений через code review
- Автоматическое применение security best practices
- Прозрачность конфигурации безопасности

## Соответствие требованиям "Будущего 2.0"

### Производительность
- Современные инстансы стандарта standard-v3
- Быстрые SSD диски для критичных операций

### Надежность
- Автоматическое восстановление при сбоях
- Резервное копирование данных

### Безопасность
- Детальные security groups
- Изоляция внутренних сервисов
- Использование service accounts

### Экономическая эффективность
- Раздельное хранение активных данных и бэкапов
- Возможность автоматического масштабирования
